# Web Push Notifications in AquaWise

AquaWise integrates standards-based Web Push delivery (RFC 8030 / RFC 8291 / RFC 8292) directly with the existing notification and field state architecture. It provides real-time, actionable alerts for farmers without creating disconnected alert systems or duplicate database records.

---

## Architecture Overview

```
+-------------------------------------------------------------------------+
|                              Backend                                    |
|                                                                         |
|  [Field Sensors / Weather / Irrigation Rules]                          |
|                         │                                               |
|                         ▼                                               |
|               add_notification(...)                                     |
|             (Deduplication & Cooldown)                                  |
|                         │                                               |
|             ┌───────────┴───────────┐                                   |
|             ▼                       ▼                                   |
|     SQLite notifications     send_push_notification(...)                |
|      (Persistent DB)         (Reads push_subscriptions table)           |
|                                     │                                   |
|                                     ▼                                   |
|                                pywebpush                                |
|                        (VAPID RFC 8292 signing)                         |
+─────────────────────────────────────┼───────────────────────────────────+
                                      │ HTTPS Web Push Protocol
                                      ▼
                      Push Service (Google / Mozilla / Apple)
                                      │
                                      ▼
+─────────────────────────────────────────────────────────────────────────+
|                             Frontend                                    |
|                                                                         |
|                 service-worker.js (push listener)                       |
|                         │                                               |
|                         ▼                                               |
|               showNotification(title, options)                          |
|                         │                                               |
|                         ▼ User clicks notification                      |
|           notificationclick event -> opens /?notificationId=XYZ         |
|                         │                                               |
|                         ▼                                               |
|           AquaWise UI opens & highlights matching alert in-app          |
+-------------------------------------------------------------------------+
```

### Key Principles
1. **Single Source of Truth**: Push delivery is an output channel for existing in-app notifications generated by `add_notification()`. Push failure never invalidates or deletes stored in-app notifications.
2. **Push Delivery Guarded by Settings**: Push notifications are only dispatched when notifications are enabled in farmer settings (`settings.notificationsEnabled == true`).
3. **No Duplicate Alerts**: State transitions and alerts have 2-hour deduplication windows and state transition checks to prevent notification spam from polling or SSE updates.
4. **Device Token Authorization**: Push subscriptions are tagged with an ephemeral `deviceToken`. Devices cannot view, overwrite, or unsubscribe endpoints registered by other devices (enforced with HTTP 403 Forbidden).
5. **Automatic Cleanup of Expired Subscriptions**: If a push service returns HTTP 404 Not Found or HTTP 410 Gone, AquaWise immediately prunes that subscription from the database.

## Configuration & Environment Variables

Web Push requires VAPID (Voluntary Application Server Identification) keys. Set the following environment variables in your `.env` or production deployment environment:

| Variable | Description | Example |
|---|---|---|
| `VAPID_PUBLIC_KEY` | P-256 base64url uncompressed public key (65 bytes) | `BNx...=` |
| `VAPID_PRIVATE_KEY` | P-256 base64url private key (32 bytes) or PKCS#8 PEM | `u7y...=` |
| `VAPID_CLAIMS_SUB` | Contact email or URL for the push service | `mailto:support@aquawise.farm` |
| `GOOGLE_WEATHER_API_KEY` | *(Optional)* Google Weather API key (falls back to Open-Meteo) | `AIzaSy...` |

> [!WARNING]
> **Never commit `.env` or VAPID private keys to Git.** If a secret is ever checked into source control, it must be rotated immediately.

## Generating VAPID Keys

AquaWise includes a dedicated utility script to generate cryptographic P-256 VAPID keys:

```bash
python backend/generate_vapid_keys.py
```

This script will output:
```
======================================================================
               AquaWise VAPID Keypair Generated
======================================================================

Add these variables to your .env file or production environment:

VAPID_PUBLIC_KEY="BCb..."
VAPID_PRIVATE_KEY="q8d..."
VAPID_CLAIMS_SUB="mailto:farmer-support@aquawise.farm"

======================================================================
```

If no VAPID keys are specified in the environment during backend startup, AquaWise generates an in-memory ephemeral keypair for local development with a warning. For persistent subscriptions across server restarts, add the generated keys to `.env`.

## Endpoints

### 1. `GET /api/push/vapid-public-key`
Returns the public key required for the browser's `pushManager.subscribe(...)`.
```json
{
  "publicKey": "BCb...",
  "status": "configured"
}
```

### 2. `POST /api/push/subscribe`
Registers or updates a browser push subscription.
```json
{
  "endpoint": "https://fcm.googleapis.com/fcm/send/...",
  "keys": {
    "p256dh": "...",
    "auth": "..."
  },
  "deviceToken": "device-uuid-v4",
  "userAgent": "Mozilla/5.0..."
}
```
**Response:** `{"success": true, "status": "subscribed"}`

### 3. `POST /api/push/unsubscribe`
Unsubscribes a browser endpoint. Enforces that the `deviceToken` matches the one stored with the subscription.
```json
{
  "endpoint": "https://fcm.googleapis.com/fcm/send/...",
  "deviceToken": "device-uuid-v4"
}
```
**Response:** `{"success": true, "status": "unsubscribed"}`

### 4. `POST /api/push/test`
Sends a test notification to all active push subscriptions and saves an in-app notification record.
```json
{
  "title": "AquaWise Test Alert",
  "detail": "Test notification message"
}
```
**Response:** `{"success": true, "sent": 1, "failed": 0, "notificationId": "notif-uuid"}`

## Farmer Alert Triggers

AquaWise pushes notifications on critical, actionable field events:

1. **Soil Moisture Depletion**:
   - Triggers when root-zone moisture drops below the refill threshold (`fieldState.refillPoint`).
   - Title: `Watering Recommended: Soil Moisture Critical`
2. **Irrigation Recommendation Transitions**:
   - Transition to `WATER NOW`: Direct call to action when soil and weather conditions demand irrigation.
   - Transition to `WAIT` with Rain Forecast: Informs the farmer that irrigation is delayed because rainfall is expected, saving water.
   - Transition to `CHECK FIELD`: Informs the farmer of potential sensor anomalies or field runoff risk.
3. **Sensor Faults**:
   - Triggers when telemetry is missing, stale, or reporting disconnected values.
4. **Weather Service Degradation**:
   - Triggers if both primary and secondary weather providers fail to provide forecasts.
5. **Manual / Scheduled Watering**:
   - Triggers when irrigation valve cycles start or stop.

## Frontend Integration & Service Worker

### Settings Component (`WebPushSettings`)
Located at [frontend/src/components/web-push-settings.tsx](file:///e:/Projects/AquaWise/frontend/src/components/web-push-settings.tsx) in the **Settings** view:
- Displays current permission status: `Active`, `Permission Denied`, `Unsupported Browser`, or `Inactive`.
- Requests browser notification permissions only upon explicit user toggle.
- Converts the base64url VAPID public key to a `Uint8Array` buffer for `PushManager.subscribe()`.
- Persists an anonymous `aquawise_device_token` in `localStorage` for device isolation.
- Includes a **Send Test Notification** button for immediate verification.

### Service Worker (`service-worker.js`)
Located at [frontend/public/service-worker.js](file:///e:/Projects/AquaWise/frontend/public/service-worker.js):
- **Push Event Handler**: Parses the incoming JSON payload and triggers `self.registration.showNotification(title, options)` with icons, badges, vibration patterns, and metadata tag.
- **Notification Click Handler**:
  - Focuses an existing AquaWise browser tab or opens a new window with `/?notificationId=<ID>`.
  - Posts a `NAVIGATE_TO_NOTIFICATION` message to all active clients.
- **In-App Highlight**: [frontend/src/App.tsx](file:///e:/Projects/AquaWise/frontend/src/App.tsx) detects the `notificationId` from the URL or worker message, opens the notifications popover, and highlights the matching alert item.

## Local & Production Testing

### Requirements
- **HTTPS or Localhost**: The Web Push API and Service Workers require a Secure Context (`https://` or `http://localhost`).
- **Notification Permission**: Must be granted in the browser (`Notification.permission === 'granted'`).

### Automated Test Suite
Run the backend push tests with pytest:
```bash
pytest backend/tests/test_push.py -v
```
To run the full backend test suite:
```bash
pytest backend/tests -v
```

### Manual Verification
1. Start the backend: `python main.py` (port 5000).
2. Start the frontend: `npm run dev` (port 5173).
3. Open `http://localhost:5173` in Chrome, Firefox, or Edge.
4. Navigate to **Settings**.
5. Enable **Web Push Notifications**.
6. When prompted by the browser, click **Allow**.
7. Click **Send Test Notification**.
8. Verify the system tray/OS banner appears.
9. Click the notification banner and verify AquaWise opens and highlights the notification.
